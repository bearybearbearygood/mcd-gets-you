# 麦麦懂你 · mcd-gets-you

**先接住想吃的，再替你算清这一顿。**

麦麦懂你，麦麦哄你，麦麦满足你。一个基于麦当劳中国 MCP 的点餐 Skill：理解口味和点餐纠结，把餐品、份量、营养、套餐、麦金卡与优惠条件放在一起考虑，给出愿意照着点的建议。

## 从一句真实的纠结开始

> 今天非常想吃薯条，但是又担心脂肪，晚餐怎么安排？

先保留薯条，再检查主餐和配餐能怎样调整。知道中午吃了肉夹馍，不代表知道午餐的精确营养；用户想少一些脂肪，也不代表他已经给出了全天摄入上限。

> 我想吃双鱼堡，怎么点划算一点？没有麦金卡。

先保留双鱼堡，再比较当前门店下的实际买法。2026-10-16 在北京建外 SOHO A 座店的真实 MCP 试算中：

| 方案 | 实际试算金额 | 对用户的意义 |
| --- | ---: | --- |
| 双层深海鳕鱼堡单点 | 24 元 | 只想吃这个堡时，先保留单点 |
| 双鱼堡＋中薯＋中杯可乐 | 35 元 | 小食和饮料也想要时，多支付 11 元 |
| 双鱼堡四件套，未附带购卡参数 | 58.5 元 | 菜单显示的 32 元带有「随单购麦金卡优惠」条件，不能直接当作当前实付价 |

另外核实了「麦香鱼＋小杯玉米杯」14.9 元的备选，但会明确说明它换成了单层鱼堡，留给用户决定。

这是一次历史实测，不是固定价格承诺。[完整实测记录](docs/live-tests/double-fish-prices.md)和[脱敏响应摘录](evidence/live-results-2026-10-16.json)可供检查。

## 它怎样帮你决定

1. **先懂这一顿。** 记住想吃什么、在担心什么、已经选了什么；只问会改变方案的关键问题。
2. **营养按吃的算。** 套餐拆成实际选择的汉堡、小食、饮料和酱料，份量、数量和单位对齐后累计。
3. **价格按买的算。** 比较单点、套餐和当前可用优惠，核实麦金卡与券能否使用、能否叠加，再进行完整试算。
4. **把取舍说清。** 换小份、换主餐、多买或开卡才便宜时，说明具体变化，不默认替用户接受。

蛋价比是其中一个判断依据：

```text
整餐蛋价比（g/元）= 整餐蛋白质总克数 ÷ 这份方案的实际支付元数
```

不平均单品比值，不用广告起售价计算。蛋白质数据不完整时标为无法完整计算；用户不爱吃或明显多买的组合，也不会因为蛋价比高就优先。

## 谁适合使用

- 想吃麦当劳，又纠结热量、脂肪、份量和口味的人。
- 希望少花钱吃得合适，不想自己翻菜单、卡券和营养表的人。
- 对蛋白质摄入有偏好，但不想每顿都填写完整营养问卷的人。

## 安装与开始

### 1. 准备客户端与 MCP

需要一个能加载 `SKILL.md` 并调用远程 MCP 的智能体客户端，以及你本人申请的麦当劳 MCP Token。Token 获取和连接方式见[麦当劳官方接入指南](https://github.com/M-China/mcd-mcp-server)。

本项目只包含 Skill 指令与参考文件，无需启动网站或安装 Python、Node 项目依赖。大模型推理与工具执行由客户端提供。

参考 [mcp-config.example.json](mcp-config.example.json)，配置官方地址 `https://mcp.mcd.cn`，使用 Streamable HTTP 与 Bearer 认证。示例仅包含环境变量占位符；客户端若不支持自动展开，请在客户端本地私密配置中填入 Token，不要修改或上传仓库中的示例文件。

### 2. 加载 Skill

下载仓库，保留 `skill/` 中的 `SKILL.md` 与整个 `references/` 目录。

下载 [Skill 技能包](mcd-meal-guide.skill.zip)，WorkBuddy 可在「专家·技能·连接器 → 技能 → 添加技能 → 上传技能」导入并启用。[WorkBuddy 技能文档](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)说明了上传入口；不同版本对压缩包目录的要求以客户端提示为准。

也可以在能读取本地文件的客户端中打开本仓库，输入：

```text
请读取 skill/SKILL.md，按“麦麦懂你”的指令帮我规划这一顿，
需要核价时再读取它链接的参考文件，并使用已连接的麦当劳 MCP。
```

确认客户端能列出麦当劳工具，例如 `list-nutrition-foods`、`query-meals`、`calculate-price`。未接通时，Skill 会说明哪些信息尚未核实。

### 3. 直接开始对话

```text
今天特别想吃薯条，但又担心脂肪，晚餐怎么搭配？

今晚想在北京国贸附近吃麦当劳，离地铁近点，想吃有鱼的汉堡。

就吃双鱼堡吧。我没有麦金卡，怎么点合适？

这个汉堡我想保留，能不能调整一下配餐，让这一顿少花点钱？
```

门店、到店/外送、时间和会员资格会影响报价；已知的信息会沿用，缺少报价条件时先给搭配建议，再补关键问题。

## 已验证与边界

- 已实际调用营养、活动、门店、菜单、餐品详情、门店券、可领取券列表和价格试算工具，见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)。
- 营养库不一定覆盖新品，也不一定有去酱、去芝士的配料差值。特调先核实可用项，没有可靠差值就不报精确的特调营养。
- 会员与券的覆盖受当前账号、门店和渠道限制；本次无卡鱼堡场景未实测已有麦金卡权益或适用券叠加，不宣称全场景最优。
- 预设了 [13 个验收场景](skill/references/acceptance-cases.md)。它们是验收输入与判定标准，尚不是全部通过的自动化测试；真实对话验证还应继续。
- 这份 Skill 负责查询、搭配和比较；购卡、领券、积分兑换或下单需要用户另行明确要求。本次演示未执行这些操作。
