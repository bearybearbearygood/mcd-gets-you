## 为什么做这个

蛋白质是三大营养素里最难获取的一种 —— 碳水随处可得，脂肪不请自来，唯独蛋白质，要么贵、要么麻烦：鸡胸肉得自己买自己做，外卖的「高蛋白」价格往往翻倍。

我们盯着麦当劳那 160 条营养数据算了笔账，发现一个反直觉的事实：**它是被严重低估的蛋白质来源。**

我们给它起了个名字，叫**「蛋价比」** —— 每花一块钱，能买到多少克蛋白质：

| 来源 | 蛋价比（g / 元） |
|---|---|
| 麦当劳「1+1」随心配（选双吉） | **1.81** |
| 便利店鸡胸肉三明治 | ≈1.20 |
| 外卖鸡胸沙拉 | ≈1.07 |
| 外卖牛肉饭 | ≈0.80 |

> 麦当劳为实时计算；便利店 / 外卖为常见价位估算，仅作参照。

同样一顿饭的预算，麦当劳的蛋价比能比常见外卖高出一倍。这还只是「吃蛋白质」这一件事 —— 它同时也是一个**情绪出口**：心情差时一个麦旋风真的能让人好一点，开心、有成就感时也想犒赏自己一顿。这些真实的需求，不该被一句「超标了」粗暴地否定。

所以我们想做的东西，一句话：

> **让「吃麦当劳」和「照顾好自己」不再对立。**

好好吃饭，也把饭吃好。健康和治愈，本来就不该是二选一。

## 这是什么

**不是一个热量计算器。**

市面上的营养工具都在做同一件事：把你点的东西换算成数字，然后告诉你「超标了」。它们把判断的责任丢回给你 —— 你还是得自己想：那我到底该点什么？

**麦麦懂你反过来做：先算你今天缺什么，再倒推这顿该点什么。**

```
你今天还缺 38g 蛋白，剩余热量预算 1200kcal、钠 1400mg
    ↓
推荐：巨无霸三件套（巨无霸 + 中薯条 + 热浓浓黑巧中杯）
      蛋白 41g / 978kcal / 钠 1227mg
    ↓
换购建议：可乐 → 热浓浓黑巧中杯（蛋白 +10g，差价 +11 元）
```

一句「今天该吃什么」，背后是缺口、预算、在售菜单和换购空间的联合求解。

## 它做了什么

**1. 反解缺口，而不是统计热量**

不回答「你刚吃了多少」，而是回答「你接下来该点什么」。前者是记录，后者是决策。

**2. 把钠当成一等约束**

为什么偏偏是钠？因为它是麦当劳里最容易被忽视、却最该管的健康项：

- 补蛋白质的代价里，热量和脂肪可以用「选脆汁鸡」这类办法绕开，**钠绕不开** —— 实测补足 60g 蛋白，任何组合都会用掉钠预算的一大半；
- 《中国居民膳食指南》建议每日钠摄入低于 2000mg（约 5g 盐），而麦当劳一顿正餐轻松吃掉一半；
- 高钠是高血压与水肿的主要诱因，恰恰是「想吃好又怕不健康」的人最该盯的一项。

所以我们把钠和热量、脂肪一样，作为推荐时的显式约束 —— 超出了就如实说，而不是挑个好看的数字报给你。

**3. 把「换购」当成一层独立的优化**

同一个巨无霸三件套，可乐换纯牛奶只加 ¥0.5、蛋白多 7g，换热浓浓黑巧加 ¥11、蛋白多 10g。**套餐怎么换购，是独立于「点哪个套餐」的一层决策**，我们单独做了求解。

**4. 把「今天正好有券」算进推荐**

推荐前会先读你名下的券，逐张校验今天、此刻、这个时段能不能用，再关联到具体商品：今天双吉也行、麦香鸡也行，但你正好有麦香鸡的券，那就推麦香鸡。券只在「营养打平」时起作用，不压过营养。

## 麦麦怎么「懂」你

同一份营养数据，在不同状态下答案不一样。麦麦会先问（或从你的话里读出）今天是什么状态：

| 状态 | 麦麦的调整 | 不变的部分 |
|---|---|---|
| **平常日** | 标准目标，蛋白优先 | 热量与钠都守住 |
| **运动 / 重体力后** | 热量预算放宽 20% | 钠仍守死 |
| **心情需要照顾** | 允许脂肪与碳水适度超出 | 蛋白必须补足、钠不放松 |
| **今天很开心 / 值得奖励** | 允许用一点甜或高热量犒赏自己 | 蛋白照补、钠不放松 |
| **赶时间 / 加班** | 不追求最优，选好拿好吃的 | 钠仍守死 |
| **熬夜 / 没睡好** | 避开高糖高脂，选蛋白足、升糖稳的 | 热量收着点 |
| **减脂期** | 热量收紧，但不许亏蛋白 | 钠不放松 |
| **增肌期** | 蛋白目标提高 25%，热量放宽 | 钠仍守死 |
| **肠胃不适 / 不舒服** | 避开油炸重口，选清淡易消化 | 蛋白也要补 |

**核心原则：每次只放宽一个维度，其余照守。**

**除了「今天什么状态」，还有「现在几点」。**

同一份缺口，早上 8 点和晚上 8 点问，答案不一样 —— 不仅因为菜单分时段（早餐 / 正餐 / 下午茶 / 夜宵的菜品不同，接口会按时间返回对的那一份），更因为这顿饭在一天里的位置不同：

| 时段 | 目标 |
|---|---|
| **早餐**（一天第一顿） | 启动代谢，蛋白要够，碳水可以放宽 |
| **午餐**（承上启下） | 按标准目标走 |
| **下午茶**（小补一口） | 别影响晚餐 |
| **晚餐**（今天最后一顿） | 总量收着点，但蛋白别缺 |
| **夜宵**（尽量轻） | 避免高脂高碳水影响睡眠 |

所以「今天心情不好想吃麦旋风」的回应不是「超标了不建议」，而是：

> 麦旋风可以。但今天蛋白还缺 25g —— 顺手加一份脆汁鸡里脊（126kcal / 19g 蛋白 / 脂肪仅 2g），甜也吃了，蛋白也补上了，钠还在线内。

**不评判你的选择，只优化你的代价。**

## 它用的数据

全部来自麦当劳 MCP，不做任何臆造：

| 数据 | 来源 Tool | 实测规模 |
|---|---|---|
| 营养表 | `list-nutrition-foods` | 160 条，蛋白 / 脂肪 / 碳水 / 钠 / 钙五项完整 |
| 门店 | `query-nearby-stores` | 按城市与关键词检索 |
| 在售菜单与价格 | `query-meals` | 单店 119 项，全部含现价，且分时段 |
| 套餐结构与换购差价 | `query-meal-detail` | 每轮候选、差价、特制项 |
| 优惠券 | `query-my-coupons` | 券名、用券价、有效期（精确到星期与时段） |
| 服务端时间 | `now-time-info` | 用于判断当前时段 |
| 价格核算 | `calculate-price` | 实付价（单位为分） |

### 一个真实的数据事实

按「每克蛋白要付出多少热量」把含蛋白产品排序，差距比想象中大：

| 产品 | 热量 | 蛋白 | kcal / 克蛋白 |
|---|---:|---:|---:|
| 蒜了吧黄油风味薄皮脆汁鸡·带骨里脊 | 126 | 19g | **6.6** |
| 蜜汁BBQ风味薄皮脆汁鸡·带骨里脊 | 152 | 20g | 7.6 |
| **双层吉士汉堡** | 429 | 27g | **15.9** |
| 巨无霸 | 513 | 27g | 19.0 |
| 麦辣鸡腿汉堡 | 485 | 24g | 20.2 |

**同样是补蛋白，效率差 3 倍。** 这个差距靠感觉看不出来，而它直接决定你这顿饭的代价。

## 快速开始

### 前置条件

| 依赖 | 说明 |
|---|---|
| 麦当劳 MCP Token | 在 <https://open.mcd.cn/mcp> 手机号登录 → 控制台 → 激活后获取 |
| Python 3.10+ | 项目零第三方依赖，仅用标准库 |
| WorkBuddy | 推荐，本次活动官方合作伙伴 |

### 1. 配置麦当劳 MCP

打开 WorkBuddy → 左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置 MCP】，粘贴 [`mcp-config.example.json`](./mcp-config.example.json) 的内容，把 `${MCD_MCP_TOKEN}` 换成真实 Token 后保存启用。

### 2. 验证连通

```bash
export MCD_MCP_TOKEN="你的 Token"
python3 skill/mcd_client.py list
```

### 3. 用起来

在对话框里直接说人话：

```
今天蛋白还差不少，想吃麦当劳，别太油
今天跑了 15 公里，想补点蛋白
今天心情不好，想吃麦旋风，但不想让今天白费
```

麦麦会先算出缺口，再给出方案和代价明细。

## 目标用户

- **健身 / 增肌人群**：知道蛋白重要，但每天手动查表算缺口太累
- **减脂但不想亏蛋白的人**：控制热量时最容易把蛋白一起砍掉
- **天天吃麦当劳的上班族**：想吃好一点，又不想每顿都做数学题

共同点是：**他们不是不知道该吃好，是不想每顿饭都当一次营养师。**

## 已知边界

如实列出当前限制，而不是假装它们不存在：

1. **营养表覆盖不全。** 营养表 160 条与门店在售 119 项之间，直接匹配率约 31% —— 营养表既不含套餐、也缺新品。套餐已通过拆解子项解决，新品只能等数据源更新。
2. **特制项的营养增减是估算值。** 接口只提供特制项清单，不提供每项的营养变化量。项目内建了一张估算表补上这一环，所有相关输出都会标注「估算值，非官方数据」。
3. **价格维度尚在开发。** 菜单价格与换购差价已在数据结构中打通，但「含券实付价 / 麦金卡价」的核算逻辑仍在验证，将在下一版提供。
