# 实测：新品中有没有热量较低的选项

## 测试上下文

用户午餐吃过肉夹馍，晚餐希望有些变化，随后询问新品，再问「新品有什么热量低的选项吗？」。未确认预算、热量上限，也未排除汉堡或辣味。

本次测试验证真实 MCP 数据能否支持回答，不执行点餐或领券。

## 调用与结果

使用 WorkBuddy 已有的 mcd-mcp 配置连接 https://mcp.mcd.cn；未复制认证信息。服务器报告 mcd-mcp 1.0.0，工具清单共 35 项。

| 工具 | 参数 | 接口返回时间 | 结果 |
| --- | --- | --- | --- |
| list-nutrition-foods | {} | 2026-10-16 14:37:49 | success=true，code=200，160 条营养记录 |
| campaign-calendar | {} | 2026-10-16 14:37:51 | success=true，code=200，返回活动日历 |

活动日历 2026-10-16 的 articleDto.title/content 提及：

- 龙焰鸡腿堡、龙焰芝士棒鸡腿堡。
- 韩式辣椒黄油风味酱、韩式烟熏芝士风味酱，以及鸡薯双全盒、蘸酱炸鸡。
- 蓝莓爆爆珠麦旋风。
- 灰焰圆筒。

对营养库 productName 检索「龙焰、芝士棒、心形、脆皮鸡柳、烟熏、牧场、蓝莓、灰焰」，均为 0 条匹配。由此只能判定本次返回数据尚未匹配到这些新品的营养条目，不能断言其他渠道没有相关资料。

活动宣传不等于指定门店实时有货；活动起售价不等于实际成交价。本次未查询门店菜单或结算价格。

## 被测 Skill 应如何继续

> 查到这轮新品了，但 MCP 营养库里没有匹配到龙焰汉堡、鸡薯双全盒、新麦旋风和灰焰圆筒的完整热量数据，目前没法可靠地排出谁更低。你更想保留「尝新品」，还是优先选「热量有数据可查」的？

这时追问有明确作用：决定在数据不足时保留哪项偏好。无需先追问用户全天三餐、身体信息或精确热量目标。

## 判定

- 已验证：认证连通、工具调用、活动信息读取、营养库名称匹配。
- 未验证：新品热量排序、对应门店可售情况、蛋价比及用户对推荐的接受度。
- 应避免：把常规圆筒热量套给灰焰圆筒；把常规鸡腿堡套给龙焰系列；只计算盒内部分食品就当作整盒总热量；把缺失数据当成 0。
- 本用例应进入「营养数据不足，澄清优先级」分支，而不能声称已经找到低热量新品。
